# Massive MIMO Antenna Panel Muting Validation with Sionna RT

A reproducible ray-tracing validation of rank-one (RI=1) single-user massive MIMO
downlink beamforming and **antenna-panel muting** in the 3GPP-style Ginza urban
scene. The project uses NVIDIA Sionna RT to simulate the physical channel and a
small, self-contained Python library to build the DFT codebook, sweep beams,
select a PMI, and compare **normal** (full 128-port panel) versus **sleep**
(right-half panel muted) link performance.

> **Scope statement:** This is a **physical-layer link-budget validation**, not a
> complete ML project and not a system simulator. It does **not** implement MCS
> selection, BLER, explicit ISI/ICI, MU-MIMO, scheduling, or OTA measurements.

---

## Research question

Massive MIMO base stations can save RF power by muting part of the antenna panel
while keeping the same digital precoder. For a rank-one DFT beam, the right-half
panel muting mask removes 64 of 128 TX ports. The theoretically expected wideband
power reduction is 3 dB in linear power (6 dB in voltage-weighted gain), but the
actual loss experienced at the receiver depends on the channel geometry, beam
pattern, and scattering environment.

This project answers:

1. How close is the observed sleep-mode SNR loss to a simple **fixed 6 dB rule**?
2. Does the loss vary enough across UE locations to make prediction worthwhile?
3. What physical features (LOS/NLOS, RMS delay spread, PMI consistency) correlate
   with deviations from 6 dB?

## System configuration

| Parameter | Value |
|---|---|
| Carrier frequency | 3.5 GHz |
| Bandwidth | 100 MHz |
| Subcarrier spacing | 30 kHz |
| Active subcarriers | 3,276 (273 RB × 12) |
| TX ports | 128 (8 physical rows × 8 columns × 2 cross polarizations) |
| TX array logic | `ArrayConfig(num_subarray_rows=4, num_horizontal=8, elements_per_subarray=2, num_polarizations=2)` |
| TX element pattern | TR 38.901 |
| TX polarization | Cross-pol (`cross`) |
| RX ports | 2 (single dual-polarized isotropic element, `iso`/`VH`) |
| Spatial codebook | DFT, 8 vertical × 32 horizontal beams |
| Co-phasing (`i2`) | 4 choices |
| Total codebook beams | **1,024** |
| Normal TX power | 51.13 dBm total |
| Noise figure | 5 dB |
| Temperature | 290 K |
| Scene | Ginza (`ginza_1.xml`) from Sionna RT examples |
| Solver | Sionna RT `PathSolver`, max_depth=15, seed=36, LOS + specular + diffuse reflection |

The sleep codeword is generated by taking the **same rank-one DFT beam** selected
in normal mode and applying a **right-half physical-port muting mask**. The
mask keeps columns `[0, num_horizontal/2)` active and mutes columns
`[num_horizontal/2, num_horizontal)`. Because the weights are not re-normalized,
the active ports still carry the same per-chain power:

```text
||w_normal||^2 = 1
||w_sleep||^2  = 0.5
```

Both normal and sleep share the **same propagation paths**, the **same wideband
CFR `H`**, and the **same selected PMI**. Only the beamforming weights differ.

## Core architecture

```text
src/mMIMO_sleep/
├── array_config.py          # Single source of truth for 128-port array
├── codebook/
│   ├── dft.py               # Generate rank-one DFT codebook
│   ├── pmi.py               # PMI(i11,i12,i2) <-> flat beam index
│   ├── muting.py            # Right-half panel muting mask
│   └── pmi_mask.py          # Valid-PMI mask (metadata only)
├── simulation/
│   └── sionna_array.py      # ArrayConfig -> Sionna PlanarArray
└── data/
    ├── schema.py            # Dataset schema (63 fields)
    ├── ginza_config.py      # Config loader + hash
    ├── ginza_sample.py      # Single-UE simulation
    ├── ginza_pipeline.py    # Resumable 100-UE pipeline
scripts/
└── generate_ginza_dataset.py  # CLI entry point
notebook/
└── ginza_single_ue_cfr_normal_sleep.ipynb  # Canonical single-UE notebook
```

Key design choices:

- **Full-codebook sweep:** all 1,024 beams participate in normal-mode selection;
  `valid_pmi_mask` and `selected_pmi_valid` are recorded only as metadata.
- **No pre-filtering of NLOS or invalid PMIs:** every UE that has paths is kept.
- **Complex path coefficients:** Sionna RT returns `paths.a` as a `(real, imag)`
  tuple; we reconstruct `paths.a[0] + 1j * paths.a[1]` before forming the PDP.
- **CFR consistency check:** center-frequency CFR and the 0 Hz subcarrier of the
  wideband CFR are asserted with `rtol=1e-4, atol=1e-12`.

## Installation and running

### 1. Clone and install

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,rt]"
```

The `rt` extra pins `sionna-rt==1.2.2`. Do not upgrade to 2.x.

### 2. Run tests

```bash
PYTHONPATH="$PWD/src" python -B -m pytest -p no:cacheprovider tests/ -q
/opt/venv/bin/ruff check src/mMIMO_sleep tests
```

Current status: **186 tests passed**, ruff clean.

### 3. GPU smoke test

```bash
/opt/venv/bin/python /opt/smoke_test.py --mode gpu
```

### 4. Single-UE reproduction (canonical UE index 1)

```bash
PYTHONPATH="$PWD/src" python -B \
  scripts/generate_ginza_dataset.py \
  --config configs/ginza_dataset_v1.yaml \
  --start-index 1 \
  --stop-index 2 \
  --output-dir outputs/ginza_single_ue \
  --format jsonl
```

Expected values for UE 1:

| Metric | Value |
|---|---|
| center PMI | (24, 1, 0) |
| wideband PMI | (23, 1, 0) |
| normal RX power | ~ -107.05 dBm |
| sleep RX power | ~ -112.20 dBm |
| normal SNR | ~ 17.16 dB |
| sleep SNR | ~ 12.01 dB |
| power-weighted mean delay | ~ 1.45 µs |
| RMS delay spread | ~ 0.14 µs |

### Spatial pattern

The loss is fairly uniform across the Ginza scene, with a slight tendency for
lower loss (larger than 6 dB deviation) in NLOS regions where the dominant
scatterer comes from the active half of the panel.

![UE spatial loss map](docs/assets/ue_spatial_loss_map.png)

| Feature | Pearson r | Spearman ρ |
|---|---|---|
| `center_and_wideband_pmi_differ` | -0.37 | -0.43 |
| `rms_delay_spread_s` | -0.25 | -0.48 |
| `normal_snr_db` | +0.12 | +0.11 |
| `tx_ue_distance_2d_m` | +0.02 | +0.03 |

Correlation is reported descriptively, not causally.

## Known limitations

1. **No ML model is trained or shipped.** The EDA showed that the sleep loss is
   tightly centered around 6 dB; a regression model would mostly learn a constant.
2. **No MCS / BLER.** Only SNR and received power are reported.
3. **No explicit ISI/ICI simulation.** OFDM parameters are recorded but not used
   to simulate waveform-level interference.
4. **No MU-MIMO or scheduling.** Single-user, single-TX link only.
5. **LOS classification is heuristic.** Based on geometric delay matching, not a
   native Sionna RT path-type label.
6. **Power-weighted delay is a proxy.** It is not a quantized 3GPP Timing Advance
   command.
7. **Scene dependency.** End-to-end ray-tracing requires the Ginza scene assets,
   which are not distributed with this repository.
8. **Public asset policy.** Original Ginza XML/mesh, `rx_1000.pkl`, the full 100-UE
   dataset, and executed notebooks are **not** committed.

## Future work

The current RI=1 experiment establishes the physical baseline. More interesting
ML and system problems are likely in the following directions:

1. **Per-subcarrier worst-case analysis.** Instead of predicting average loss,
   model the sleep-mode p5 SNR or the number of subcarriers below an MCS
   threshold.
2. **Sleep beam reselection gain.** Does re-optimizing the PMI after muting
   recover part of the loss?
3. **Alternative muting patterns.** Compare left-half, checkerboard, or
   interleaved muting masks.
4. **Rank > 1 and MU-MIMO.** Extend to multi-layer precoding and multi-user
   geometry.
5. **MCS/BLER bridge.** Map per-subcarrier SNR to a chosen MCS and estimated
   block-error rate.
