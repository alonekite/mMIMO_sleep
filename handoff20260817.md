## 3. CUDA Initialization Failure

After the initial `pip install -e ".[dev,rt]"`, PyTorch could not see the GPU:

```text
PyTorch: 2.13.0+cu130
PyTorch CUDA runtime: 13.0
torch.cuda.is_available(): False
```

with the warning/error:

```text
UserWarning: CUDA initialization: Unexpected error from cudaGetDeviceCount().
Did you run some cuda functions before calling NumCudaDevices() that might have already set an error?
Error 804: forward compatibility was attempted on non supported HW
(Triggered internally at /__w/pytorch/pytorch/c10/cuda/CUDAFunctions.cpp:119.)
```

### Root cause

The RunPod container image contained a forward-compatibility driver library path registered in `ldconfig`:

```text
/etc/ld.so.conf.d/00-compat-067bd2ca-11bf-46f8-b40b-5b6b3a02d962.conf
/usr/local/cuda-13.1/compat
```

This directory contains `libcuda.so.590.48.01` and related libraries. It was placed ahead of the host driver library (`/lib/x86_64-linux-gnu/libcuda.so.580.159.04`) in the dynamic linker cache. The RTX 4090 is a consumer GPU and does not support NVIDIA forward compatibility, so `cudaGetDeviceCount()` returned error 804.

This is a **CUDA driver/library initialization problem**, not a bug in Sionna RT, Mitsuba, Dr.Jit, or the project Python code.

## 4. Resolution

Two steps were required.

### 4.1 Switch PyTorch from the CUDA 13.0 wheel to the CUDA 12.6 wheel

```bash
.venv/bin/pip install --force-reinstall \
  torch==2.13.0+cu126 \
  --index-url https://download.pytorch.org/whl/cu126
```

This replaced:

- `torch==2.13.0+cu130`
- the `cuda-toolkit==13.0.3` PyPI bundle (`nvidia-*-cu13` packages)

with:

- `torch==2.13.0+cu126`
- the `cuda-toolkit==12.6.3` PyPI bundle (`nvidia-*-cu12` packages)

CUDA 12.6 is compatible with the host driver 580.159.04 via backward compatibility, which works on the RTX 4090.

### 4.2 Remove the forward-compatibility path from the dynamic linker cache

```bash
mv /etc/ld.so.conf.d/00-compat-067bd2ca-11bf-46f8-b40b-5b6b3a02d962.conf \
   /etc/ld.so.conf.d/00-compat-067bd2ca-11bf-46f8-b40b-5b6b3a02d962.conf.bak
ldconfig
```

After this, `ldconfig -p | grep libcuda.so` resolves to the host driver library:

```text
libcuda.so.1 (libc6,x86-64) => /lib/x86_64-linux-gnu/libcuda.so.1
libcuda.so (libc6,x86-64)   => /lib/x86_64-linux-gnu/libcuda.so
```

Both steps are necessary: switching to cu126 alone was not sufficient because the linker still preferred the broken forward-compat `libcuda.so`.

## 6. Dependency Reproducibility Risk

`pyproject.toml` currently defines:

```toml
dependencies = [
    "matplotlib>=3.8,<4",
    "numpy>=1.26,<2",
    "torch>=2.2,<3",
]

[project.optional-dependencies]
dev = [ ... ]
rt = [
    "sionna-rt==1.2.2",
]
```

### Risk

A plain reinstall from the default PyPI index:

```bash
.venv/bin/pip install -e ".[dev,rt]"
```

will resolve `torch>=2.2,<3` to `torch==2.13.0+cu130` again, because the default PyPI index in this environment serves `torch==2.13.0` with CUDA 13.0. That will re-introduce the forward-compatibility failure on the RTX 4090.

### Recommended reproducible install order

1. Create the venv and install the project (this gets the CPU-only / default wheel index version of torch):

   ```bash
   python3.11 -m venv .venv
   .venv/bin/pip install --upgrade pip
   .venv/bin/pip install -e ".[dev,rt]"
   ```

2. Overwrite PyTorch with the CUDA 12.6 wheel from the official PyTorch index:

   ```bash
   .venv/bin/pip install --force-reinstall \
     torch==2.13.0+cu126 \
     --index-url https://download.pytorch.org/whl/cu126
   ```

3. Verify:

   ```bash
   .venv/bin/python -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
   ```

### Note

Do not modify `pyproject.toml` to pin `torch==2.13.0+cu126`, because the `+cu126` local version cannot be expressed in a plain PEP 508 dependency without also changing the package index. The reproducible solution is either:

- Document the two-step install (as above), or
- Pin the PyTorch wheel via a separate `requirements-runpod.txt` / lock file that uses the `cu126` index, or
- Use a `pip.conf` / environment variable that forces the PyTorch index for torch-related packages.
